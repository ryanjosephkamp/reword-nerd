# reword-nerd v0.7: Updates, feedback, and sharing

## At a glance

I made the release story part of the product. v0.7 adds a static Updates journal, clearer ways to send useful feedback, a small sharing flow, and a synthetic walkthrough that ties those pieces together.

## Added

- I added real static pages for the Updates archive, the Road to v0.6 retrospective, this v0.7 journal entry, an RSS feed, and a sitemap.
- I added a JSON-authoritative release ledger with release classification, publication state, local media policy, related pull requests, and reviewed Markdown custody.
- I added deterministic authoring, release-preparation, validation, and rendering commands that stay offline and make no commit or remote API call.
- I added community destinations for focused bug reports, feature ideas, discussions, contributions, the project website, and sponsorship.
- I added sharing controls that use the platform share sheet when available and a copy-link fallback when it is not.

## Changed

- I changed the production build so it validates the ledger, Markdown, versions, and local media before Vite runs, then renders the static Updates files into the finished site.
- I grouped product, community, and creator information more clearly while keeping the narrow mobile workbench focused on the document workflow.
- I moved the application version to 0.7.0 while keeping prompt-package manifest schema 6 and workbook progress schema 1.

## Fixed

- I made version disagreement, missing current releases, draft release prose, unsafe Markdown, remote media, broken paths, and unfinished placeholders fail closed.
- I made release preparation idempotent and protected edited prose from being overwritten on a repeated run.
- I kept shared links on the canonical clean Updates URL so local UI state is not exposed.

## Why this matters

Release notes are most useful when they explain more than a version number. The ledger gives the build a strict machine-readable contract, while the journal gives me room to explain decisions, limitations, and exact verification in a voice that is still readable without JavaScript.

## See it in action

The v0.7 walkthrough opens Updates, shows the feedback routes, and demonstrates Share with synthetic content. The video, poster, and transcript are same-origin release assets; the page never requires a third-party player.

## How to use it

Open Updates from the workbench information menu or visit the Updates archive directly. Choose a post to read the full builder's journal, subscribe to the RSS feed if you want release summaries, use a feedback link when you have a concrete report or idea, and choose Share to send the canonical post URL.

## Compatibility and limitations

Updates pages are deliberately static and do not use an SPA or hash router. Native sharing depends on browser support; the copy fallback remains available where the Web Share API is missing or rejects the request. Automated browser coverage remains Chromium-focused, so the release does not claim complete cross-browser verification.

## Privacy

The workbench remains browser-only. There is no backend, account, analytics, telemetry, model or provider call, credential flow, remote asset, service worker, or new persistence for uploaded documents. The sole storage key remains `reword-nerd:preferences:v1`. Updates media is synthetic and separate from session content.

## Verification

The release pipeline exercises ledger safety, remote-media rejection, version and schema agreement, deterministic authoring, edited-prose preservation, static semantic HTML, canonical and social metadata, JSON-LD, RSS, and sitemap output. The full release gate also runs lint, TypeScript, unit tests, the production build, focused Chromium flows, privacy scans, and a clean-diff check.

## What comes next

I want to keep the journal small and honest: one reviewed entry per meaningful release, concise RSS summaries, and media only when it clarifies a visual change. Future entries should grow from the same local, deterministic release inventory rather than generated marketing prose.
