# reword-nerd v0.7: Static Updates journal

## At a glance

I made the release story part of the product. v0.7 adds a static Updates journal, a machine-readable release ledger, and deterministic preparation for reviewed release notes.

## Added

- I added real static pages for the Updates archive, the Road to v0.6 retrospective, this v0.7 journal entry, an RSS feed, and a sitemap.
- I added a JSON-authoritative release ledger with release classification, publication state, local media policy, related pull requests, and reviewed Markdown custody.
- I added deterministic authoring, release-preparation, validation, and rendering commands that stay offline and make no commit or remote API call.

## Changed

- I changed the production build so it validates the ledger, Markdown, versions, and local media before Vite runs, then renders the static Updates files into the finished site.
- I moved the application version to 0.7.0 while keeping prompt-package manifest schema 6 and workbook progress schema 1.

## Fixed

- I made version disagreement, missing current releases, draft release prose, unsafe Markdown, remote media, broken paths, and unfinished placeholders fail closed.
- I made release preparation idempotent and protected edited prose from being overwritten on a repeated run.

## Why this matters

Release notes are most useful when they explain more than a version number. The ledger gives the build a strict machine-readable contract, while the journal gives me room to explain decisions, limitations, and exact verification in a voice that is still readable without JavaScript.

## See it in action

This release does not yet publish a walkthrough video. The ledger declares the visual update and records a reviewed exemption; any future clip must use same-origin synthetic media with a local poster and transcript before the page renders it.

## How to use it

Visit the Updates archive directly, choose a post to read the full builder's journal, and subscribe to the RSS feed if you want concise release summaries. Repository feedback links remain available below, while any in-workbench feedback or Share controls are outside this static-journal release.

## Compatibility and limitations

Updates pages are deliberately static and do not use an SPA or hash router. The static engine does not implement a Share control or a release video. Automated browser coverage remains Chromium-focused, so the release does not claim complete cross-browser verification.

## Privacy

The workbench remains browser-only. There is no backend, account, analytics, telemetry, model or provider call, credential flow, remote asset, service worker, or new persistence for uploaded documents. The sole storage key remains `reword-nerd:preferences:v1`. No release video is shipped by this entry.

## Verification

The release pipeline exercises ledger safety, remote-media rejection, version and schema agreement, deterministic authoring, edited-prose preservation, static semantic HTML, canonical and social metadata, JSON-LD, RSS, and sitemap output. Before publication, I also run lint, TypeScript, the full unit suite, a Pages-base production build, browser checks, privacy-boundary scans, and `git diff --check` as explicit release gates.

## What comes next

I want to keep the journal small and honest: one reviewed entry per meaningful release, concise RSS summaries, and media only when it clarifies a visual change. Future entries should grow from the same local, deterministic release inventory rather than generated marketing prose. Any feedback, Share, or release-media work will need its own review before this journal claims it is available.
